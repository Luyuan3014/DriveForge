Three Core Invariants

坚守工程底线的三大不变量

大语言模型很容易凭空捏造引脚定义与外设寄存器。DriveForge 专为嵌入式确定性而生，每一行配置和代码均具备完整证据链。

INVARIANT 01

证据链优先，拒绝凭空臆造

引脚、PinMux、RCU/APB 时钟、中断向量 IRQ 必须源自明确的用户输入、工程头文件、板级配置或官方 SDK。若关键证据不足，直接进入 BLOCKED 状态。

✓ Evidence-backed Facts
INVARIANT 02

复用优先，极简代码侵入

严守 已有工程实现 → 同系列芯片驱动 → 官方 BSP 驱动 → 厂商 SDK → 全新编写 的降级策略。尽可能保留项目原汁原味的编码习惯，绝不进行盲目暴力重构。

✓ Adapt First, Rewrite Last
INVARIANT 03

显式授权，实机闭环验证

阶段职责边界分明：编译通过不等于烧录成功，烧录成功不代表外设在真实物理总线上正常运转。显式接入 J-Link、OpenOCD、ST-Link 与 RTT/串口回环，实测通过才评定为 VERIFIED。

✓ Closed-Loop Verification

01 / HARDWARE MANIFEST ENGINE

硬件事实清单与置信度追溯

DriveForge 的 Analyzer 会全面扫描目标工程中的 C/C++ 源码、Kconfig、板级头文件与 SConscript。每一个识别出的外设引脚或时钟门控，都精确记录文件路径、行号与摘录证据。

  • ✓ 置信度分级：VERIFIED / HIGH / MEDIUM / LOW
  • ✓ 用户显式配置优先保护，并自动隔离标记为 user_config，绝不与工程证据混淆
  • ✓ 严格校验 GPIO 范围（如 PA0..PK15）与时钟正整数合法性
hardware_manifest.yaml GATED: PASS 
target_peripheral: "CAN0"

02 / ADAPT-FIRST PLANNER & AGY SKILL

复用规划器与 Codex/Antigravity 智能体协同

DriveForge 拥有分层的智能体架构：确定性的 CLI 负责扫描拓扑、事实门禁与测试运行，而仓库根目录的 SKILL.md 则将嵌入式专家开发规范系统化注入大模型智能体。

  • ✓ 智能识别参考实例：若工程已有 CAN1，自动生成同源适配计划（adapt_existing_instance）
  • ✓ 记录源码哈希基线（baseline.json），任何意外修改或副作用一目了然
  • ✓ 支持 commands.patch 和 commands.repair 接入自动化修复闭环

strategy: "adapt_existing_instance"
reference_file: "drivers/drv_can1.c"

03 / PLAYBOOKS & PHYSICAL LOOP

标准化外设 Playbooks 与真实回环测试

DriveForge 针对 7 大类常用外设预置了标准验收准则（Playbooks）。无论是 CAN 帧收发、UART 乱码检测、SPI Flash 读写 ID 还是 ADC 线性采样，均提供可执行的最小测试准则。

CAN Playbook 波特率自适应、回环模式验证、仲裁丢失排查
UART Playbook DMA 接收环形缓冲、波特率校验、断帧检测
SPI / I2C Playbook JEDEC ID 读取校验、ACK应答探测、时序容限
ADC / PWM Playbook 基准电压校准、多通道扫描、占空比实测

        Developer Quickstart
        

          三步接入真实工程流水线
        

        

          Python 3.10+ 原生无额外第三方依赖，可直接作为独立 CLI 运行，或与 Antigravity / Codex 插件深度整合。
        

      


      

        
        
        

          

            

              1
              
安装或直接使用源码

            

            
          

          

            # 克隆并以可编辑模式安装

            git clone https://github.com/Luyuan3014/DriveForge.git

            cd DriveForge

            python -m pip install -e .
          

        


        
        

          

            

              2
              
执行规划（生成 Manifest 与 Driver Plan）

            

            
          

          

            # 智能分析目标工程，校验硬件事实门禁，输出复用方案

            driveforge plan C:\path\to\rtthread-project \

              --request "给这个项目增加 CAN0 驱动" \

              --mcu GD32F470ZIT6 \

              --rx-pin PD0 --tx-pin PD1 \

              --clock-gate RCU_CAN0
          

        


        
        

          

            

              3
              
执行构建、烧录与硬件测试

            

            
          

          

            # 显式授权各阶段，生成最终 verification_report.yaml

            driveforge run C:\path\to\rtthread-project \

              --config driveforge.json \

              --execute-build \

              --execute-flash \

              --execute-test
          

        


      


      
      

        
工作流最终状态定义 (State Machine)

        

          

            PLANNED
            已完成分析规划，未执行验证
          

          

            BUILD_PASS
            编译构建通过，未证明硬件行为
          

          

            FLASH_PASS
            固件已成功烧录，未完成测试
          

          

            VERIFIED
            硬件测试命令通过
          

          

            BLOCKED
            关键事实缺失，安全暂停
          

          

            FAIL
            已执行的某个阶段失败
