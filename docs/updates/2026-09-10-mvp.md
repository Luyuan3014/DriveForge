# 2026-09-10：DriveForge MVP 初始实现

## 背景

DriveForge PRD 定义了一个从驱动需求到真实硬件验证的自主工程闭环。初始实现先建立可运行、可扩展的 RT-Thread 软件工作流，重点解决硬件事实不可猜测、驱动应优先复用以及构建通过不能等同于硬件验证三个问题。

## 变更范围

- 新增 Python CLI 与 `scan`、`plan`、`run` 子命令。
- 新增 RT-Thread、GD32F4/STM32F4、七类外设的范围识别。
- 新增工程拓扑、硬件事实、证据位置和置信度模型。
- 新增 Adapt First Driver Plan。
- 新增显式 Patch/Build/Flash/Test 执行和有限 Repair 循环。
- 新增源码基线、修改文件追踪、日志和 Verification Report。
- 新增 Codex Skill、七份外设 Playbook、四份 JSON Schema 和 CAN0 配置示例。
- 新增完整项目文档、Changelog 和贡献流程。

## 用户影响

用户可以对一个 RT-Thread 工程生成可审查的 Hardware Manifest 和 Driver Plan。只有关键事实完整时才能进入实现阶段；构建、烧录和测试必须分别通过命令行显式启用。

最终报告区分 `PLANNED`、`BUILD_PASS`、`FLASH_PASS`、`VERIFIED`、`FAIL` 和 `BLOCKED`。

## 兼容性

这是首个公开版本，没有历史配置需要迁移。核心运行时要求 Python 3.10 或更高版本，配置格式为 JSON。

## 验证

- 自动化测试：13 项全部通过。
- 语法检查：`src` 与 `tools` 可通过 Python 编译检查。
- CLI：源码入口和模块入口均可输出 `DriveForge 0.1.0`。
- Skill：frontmatter 和指令结构通过 Skill Creator 校验逻辑。
- 真实硬件：本次没有连接开发板或调试器，未进行真实硬件验证。

测试中的完整 `VERIFIED` 流程使用受控模拟命令，只证明状态机和报告逻辑，不代表 CAN0 驱动已在实物上通过。

## 已知限制

- 尚未完成 GD32F470 CAN0 真实 Benchmark。
- 代码修改依赖 Codex Skill 或外部 Patch/Repair 命令。
- 探针与串口命令需要项目配置，尚无内置适配器。
- 尚未提供 SVD、原理图和手册专用解析器。
